SECTION 1: COMPREHENSIVE FOLDER & FILE USE CASE BREAKDOWN
===============================================================================

-------------------------------------------------------------------------------
1.1 ROOT LEVEL PYTHON SCRIPTS & PIPELINE MODULES
-------------------------------------------------------------------------------
* `app.py`
  - Purpose: The main Streamlit web application frontend and interactive user interface.
  - Features: Features a dark/light blue UI theme, RAG Q&A query engine tab ("Ask Engine"),
    a Wiki Knowledge Explorer tab for inspecting notes and frontmatter metadata, and a
    single-field "Quick Note" input form that directly writes formatted Markdown notes to `/wiki`.

* `config.py`
  - Purpose: Central configuration module for the entire application.
  - Features: Resolves project root, loads environment variables from `.env`, defines 
    directory paths (`RAW_DIR`, `WIKI_DIR`, `DATA_DIR`, `ASSETS_DIR`, `FILES_DIR`, `EMBEDDINGS_DIR`),
    sets hyperparameters (`SIMILARITY_THRESHOLD = 0.72`, `RAG_TOP_K = 5`, `RAG_MIN_SCORE = 0.45`),
    and validates the Groq API key (`GROQ_API_KEY`).

* `capture.py`
  - Purpose: CLI capture pipeline for ingesting raw information into `raw/`.
  - Commands Supported: `note` (text notes), `link` (scrapes page title & saves URL), `file` 
    (copies binary file to `assets/files/` and extracts text from PDFs using `pypdf`).
  - Output: Generates `.md` files with structured YAML frontmatter (`id`, `captured_at`, `type`, `source`, `status: unprocessed`).

* `classify.py`
  - Purpose: Automated categorization of raw captures into the PARA wiki structure.
  - Features: Queries Groq LLM (Llama 3) to analyze capture content and assign a category 
    (`Projects`, `Areas`, `Resources`, `Archives`), generate 3-5 tags, and craft a 120-character summary.
    Includes a deterministic fallback keyword algorithm if the Groq API is offline or missing.
  - Output: Writes classified notes to `wiki/<Category>/<slug>-<id>.md` and updates `data/index.json`.

* `link.py`
  - Purpose: Semantic auto-linker using vector embeddings.
  - Features: Generates dense vector embeddings for wiki notes using SentenceTransformers 
    (`sentence-transformers/all-MiniLM-L6-v2`), computes cosine similarity pairs, and automatically
    appends bidirectional `[[wikilinks]]` between related notes exceeding the similarity threshold.

* `build_graph.py`
  - Purpose: Cartography builder for the knowledge graph.
  - Features: Scans all Markdown notes inside `wiki/`, parses YAML frontmatter and `[[wikilinks]]`,
    and outputs a structured graph payload (`nodes` and `edges`) to `data/graph.json`.

* `ask.py`
  - Purpose: Retrieval-Augmented Generation (RAG) Q&A engine for CLI usage.
  - Features: Embeds user queries, finds top-K matching notes via vector cosine similarity,
    assembles relevant note context, passes context to Groq Llama 3, and synthesizes answers with source citations.

-------------------------------------------------------------------------------
1.2 DIRECTORY STRUCTURE & SUBFOLDERS
-------------------------------------------------------------------------------

* `assets/` (Subfolder: `assets/files/`)
  - Use Case: Persistent media and document storage.
  - Details: Stores original raw binary files (PDFs, text files, images, documents) captured via `capture.py file`.
    Files are renamed with a unique short-ID prefix to prevent filename collisions.

* `components/` (File: `components/graph_view.py`)
  - Use Case: UI component layer for Streamlit.
  - Details: `graph_view.py` generates an HTML/SVG self-contained interactive component
    for rendering knowledge graph nodes and edges with category-based node colors and hover tooltips.

* `data/`
  - Use Case: System index and vector persistence layer.
  - Subdirectories & Files:
    - `data/embeddings/`: Stores individual `.json` vector files for each note containing the embedding vector, content hash, model name, and timestamp.
    - `data/graph.json`: Serialized JSON graph structure containing `nodes` (id, slug, label, category, summary) and `edges` (source, target, type).
    - `data/index.json`: Master array of all processed wiki notes with metadata and path references.

* `raw/`
  - Use Case: Landing inbox for unorganized captures.
  - Details: Contains raw `.md` files created by `capture.py`. Each file starts with `status: unprocessed`
    until `classify.py` processes it into the `wiki/` directory.

* `wiki/`
  - Use Case: Organized PARA Knowledge Base (compatible with Obsidian notes app).
  - Subdirectories:
    - `wiki/Projects/`: Time-bound projects with defined goals, milestones, and deadlines.
    - `wiki/Areas/`: Ongoing standard areas of responsibility (e.g., career, health, finance).
    - `wiki/Resources/`: Reference materials, articles, research topics, guides.
    - `wiki/Archives/`: Inactive or completed notes preserved for historical reference.
    - `wiki/.obsidian/`: Obsidian vault settings allowing users to open `wiki/` as an Obsidian Vault.

* `scripts/` (File: `scripts/setup.py`)
  - Use Case: Automation and environment initialization.
  - Details: `setup.py` ensures all required folder paths (`raw/`, `wiki/Projects`, `Areas`, `Resources`, `Archives`, `data/embeddings`, `assets/files`) exist on disk.

* `tests/`
  - Use Case: Unit test suite for verifying system functionality.
  - Files:
    - `test_capture.py`: Tests note, link, and file capture functions.
    - `test_classify.py`: Tests PARA classification logic and fallback heuristics.
    - `test_link.py`: Tests semantic embedding calculations and wikilink insertion.
    - `test_graph.py`: Tests node/edge generation for `graph.json`.
    - `test_ask.py`: Tests context retrieval, cosine scoring, and RAG answer synthesis.

* `utils/`
  - Use Case: Shared helper functions and utility libraries.
  - Files:
    - `utils/ids.py`: Generates timestamps, unique IDs, short IDs, filename formats, and slugified strings.
    - `utils/markdown.py`: Safe reading and writing of Markdown notes with YAML frontmatter headers.
    - `utils/embeddings_store.py`: Loads, saves, and validates vector embedding JSON files and content hashes.

SECTION 2: IDENTIFIED GAPS, MISSING CODE, & STRUCTURAL DEFICIENCIES
===============================================================================

1. **Graph View Component Disconnect in `app.py`**:
   - Issue: `components/graph_view.py` exists in the repository, but `app.py` does NOT currently import or display `render_graph(graph)`.
   - Impact: Users accessing the Streamlit UI cannot interact with or view the knowledge graph visually unless the tab is wired up.

2. **Simplistic Circular Node Layout in Graph View**:
   - Issue: `components/graph_view.py` uses basic trigonometric circular positioning (`Math.cos`, `Math.sin`) in raw SVG.
   - Impact: Graphs with 20+ nodes look cluttered and overlap. It lacks dynamic force-directed physics (drag, zoom, pan, physics-based edge spacing).

3. **Absence of Background Auto-Watcher Daemon**:
   - Issue: The user must manually run `python capture.py`, then `python classify.py`, then `python link.py`, then `python build_graph.py`.
   - Impact: Knowledge capture requires high manual overhead. There is no automated background daemon watching `raw/` to trigger pipeline stages automatically.

4. **Vector Search Scalability Bottleneck**:
   - Issue: Vector embeddings are saved as individual JSON files in `data/embeddings/`, and similarity search iterates linearly over files.
   - Impact: Works well for hundreds of notes, but will experience slow search latencies once the wiki grows to thousands of notes.

5. **Missing Deployment Infrastructure Files**:
   - Issue: The project lacks a `Dockerfile`, `.dockerignore`, and `.streamlit/config.toml`.
   - Impact: Deploying to container platforms (Docker, Render, Kubernetes) requires manual container configuration from scratch.

6. **Basic PDF Text Extraction (No OCR)**:
   - Issue: `capture.py` uses basic `pypdf` text extraction. Scanned PDF documents or image-only PDFs yield empty text.
   - Impact: Scanned documents cannot be searched or indexed by the RAG engine.

SECTION 3: ACTIONABLE UPGRADE SUGGESTIONS & ROADMAP
===============================================================================

-------------------------------------------------------------------------------
3.1 IMMEDIATE UPGRADES (PHASE 1 - QUICK WINS)
-------------------------------------------------------------------------------
1. **Wire Knowledge Graph Tab into `app.py`**:
   - Import `components/graph_view.py` in `app.py` and add a 4th tab: `["🔍 Ask Engine", "📂 Explore Wiki Workspace", "📝 Quick Note", "🕸️ Knowledge Graph"]`.
   - Call `render_graph(graph)` inside the tab.

2. **Upgrade Graph Rendering to PyVis / vis-network / streamlit-agraph**:
   - Replace static SVG rendering with `vis-network` force-directed physics.
   - Allow users to click on a node to view its note content immediately.

3. **Add Streamlit Theme Configuration (`.streamlit/config.toml`)**:
   - Create `.streamlit/config.toml` to enforce dark mode, custom primary colors, and font styles across all deployment environments.

4. **Add Containerization Support (`Dockerfile`)**:
   - Add a standardized `Dockerfile` and `.dockerignore` for single-command deployment to cloud providers.

-------------------------------------------------------------------------------
3.2 MEDIUM-TERM UPGRADES (PHASE 2 - AUTOMATION & SCALABILITY)
-------------------------------------------------------------------------------
1. **Build a Background Folder Watcher (`watcher.py`)**:
   - Implement `watchdog` library in `watcher.py` to monitor `raw/`.
   - When a new Markdown capture arrives, automatically run `classify -> link -> build_graph` in the background.

2. **Adopt Vector Database (ChromaDB or FAISS)**:
   - Replace file-based JSON embeddings with `chromadb` or `faiss-cpu`.
   - Enables fast similarity searches, metadata filtering by category/tags, and sub-millisecond query responses.

3. **Add OCR & Multi-Format Ingestion**:
   - Integrate `pytesseract` or `easyocr` to extract text from image-based PDFs and images (`.png`, `.jpg`).
   - Add web scraping with `beautifulsoup4` or `trafilatura` to extract full webpage articles rather than just page titles.

-------------------------------------------------------------------------------
3.3 LONG-TERM UPGRADES (PHASE 3 - ADVANCED PRODUCT FEATURES)
-------------------------------------------------------------------------------
1. **FastAPI REST API Layer**:
   - Expose endpoints (`/api/v1/capture`, `/api/v1/ask`, `/api/v1/graph`) using FastAPI.
   - Enables mobile app capture, iOS Shortcuts integration, and Chrome browser extensions.

2. **Multi-Turn Conversational Memory**:
   - Store chat conversation history in Streamlit session state and support follow-up questions ("Tell me more about the second point").

3. **Obsidian Vault Bidirectional Sync**:
   - Add two-way synchronization so changes made directly inside the Obsidian desktop application update the `data/index.json` and embeddings automatically.
